# lil-uri — Paper Tool vs readme-ai Comparison

## Methodology
Comparison of the best and worst README generated by the paper tool (README-Gen) against the README generated by readme-ai, using the evaluation framework from Section 4.4.2 of *README-Gen: Evaluating A Large Language Model for API Documentation Synthesis*.

## Paper Tool Results Summary

### Best Generated README: data2.md (CR = 66.67)
- Achieves the highest correctness among the three generated READMEs with better coverage of URI parsing and manipulation concepts. Provides more accurate installation and usage information compared to the other variants.

### Worst Generated README: data1.md (CR = 50.00)
- Lower correctness due to incomplete or inaccurate coverage of certain sections. While it still provides URI-related documentation, some sections (likely API Reference or Installation) contain gaps or inaccuracies.

## readme-ai Evaluation

### Strengths
- Correctly identifies the project title as "uri" (or "lil-uri")
- Provides accurate project structure (directory tree listing)
- Identifies JavaScript as the primary language
- Includes correct repository URL

### Weaknesses
- Empty Overview section (no description of URI parsing/manipulation)
- Features section contains only "REPLACE-ME" placeholder text
- No user-facing installation instructions (`npm install lil-uri`)
- Usage section contains only placeholder commands
- No API Reference documentation
- Does not identify the actual license
- No domain concepts (URI, parsing, query strings, protocol, host)
- No execution facts or usage patterns

### Section-by-Section Analysis
- **Title**: Correct — matches the repository name (Score: 100)
- **Overview**: Empty — no description of lil-uri as a URI parsing library (Score: 0)
- **Installation**: Provides generic `git clone` + `npm install` for development setup, but does not provide `npm install lil-uri` for end users (Score: 40)
- **Usage**: Placeholder commands only, no URI parsing or manipulation examples (Score: 0)
- **API Reference**: Absent — no documentation of URI methods (protocol(), host(), path(), query(), etc.) (Score: 0)
- **License**: Does not identify the actual license type; provides only a generic link (Score: 0)

## Conclusion
The paper tool (README-Gen) outperforms readme-ai for lil-uri documentation, though its own scores are moderate (50-66.67) compared to its performance on more popular libraries. Even the worst paper tool output (CR=50) scores 26.67 points higher than readme-ai (CR=23.33). The gap is narrower for this tool because both struggle with installation and license sections, but README-Gen still provides meaningful domain content (URI parsing concepts, usage examples) that readme-ai completely lacks (ATRAK=100 vs ATRAK=0).
